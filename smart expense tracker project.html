🏗️ Object-Oriented Architecture

The application is built in three layers — a Model layer of pure classes, a Manager layer (Singleton) that holds business rules, and a UI layer that only renders. The DOM never stores data; every rupee lives inside an object.

ClassResponsibilityOOPS Concept
TransactionAbstract base entity — id, title, amount, category, dateAbstraction
Expense / IncomeConcrete subclasses that override signedAmount()Inheritance + Polymorphism
TransactionFactoryCreates the right subclass from raw inputFactory Pattern
BudgetHolds a limit, computes usage & health statusEncapsulation
ExpenseManagerSingle source of truth for all data + business rulesSingleton + Observer
StorageSerialize / deserialize to localStorageStatic utility class
AppRenders the UI and wires user eventsSeparation of Concerns

🔒 1. Encapsulation

Data and the methods that operate on it live in the same class. Outside code can never set an inconsistent state.

class Budget {
  constructor(category, limit) {
    this.category = category;
    this.limit    = Number(limit);
  }
  usedIn(list) {
    return list
      .filter(t => t.type === 'expense' && t.category === this.category)
      .reduce((s, t) => s + t.amount, 0);
  }
  statusOf(list) {
    const p = this.usedIn(list) / this.limit * 100;
    return p >= 100 ? 'over' : p >= 80 ? 'warn' : 'good';
  }
}

🧬 2. Inheritance

Expense and Income both extend Transaction and reuse all of its shared fields and behaviour.

class Transaction {
  constructor({ id, title, amount, category, date }) {
    this.id       = id ?? uid();
    this.title    = title;
    this.amount   = Number(amount);
    this.category = category;
    this.date     = date;
  }
  get signedAmount() { return this.amount; }
}

class Expense extends Transaction {
  constructor(data) { super(data); this.type = 'expense'; }
  get signedAmount() { return -this.amount; }  // override
}

🎭 3. Polymorphism

The same call t.signedAmount behaves differently depending on the object's real class — so totals are computed in a single loop.

class Income extends Transaction {
  get signedAmount() { return this.amount; }
}

// one loop, two behaviours
totals(list) {
  return list.reduce((acc, t) => {
    acc.balance += t.signedAmount;   // polymorphic call
    return acc;
  }, { balance: 0 });
}

🔂 Singleton Pattern

Only one ExpenseManager can ever exist, so all screens read from the exact same data.

class ExpenseManager {
  static #instance = null;

  static get instance() {
    return this.#instance ??= new ExpenseManager();
  }

  constructor() {
    if (ExpenseManager.#instance) throw new Error('Use ExpenseManager.instance');
    this.transactions = [];
  }
}

🏭 Factory + 👀 Observer

The factory hides object creation; the observer makes every screen auto-refresh the instant data changes.

class TransactionFactory {
  static create(data) {
    return data.type === 'income'
      ? new Income(data)
      : new Expense(data);
  }
}

// --- Observer ---
subscribe(fn) { this._observers.push(fn); }
_notify()     { this._observers.forEach(f => f(this)); }

addTransaction(data) {
  this.transactions.push(TransactionFactory.create(data));
  Storage.save(this);
  this._notify();          // UI redraws itself
}

💾 Persistence

All data is saved to the browser's localStorage on every change, so your demo survives a page refresh. Press “Clear All Data” in the sidebar at any time to start from scratch.
